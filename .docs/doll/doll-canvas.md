# Холст куклы и позиции вещей

Создан: 2026-11-17 15:10

Как вещи ставятся на куклу и что об этом проверяет сборка. Порядок слоёв и правила замены — в [z-index.md](z-index.md).

## Холст

- Холст — `temporary-dataset/src/main/assets/doll_1.png` целиком, без обрезки. Координаты вещей отсчитываются от его левого верхнего угла в пикселях картинки.
- **Прямоугольник фигурки** — границы пикселей `doll_1.png` с альфой выше 12. Его считает сборка, вручную он не задаётся. По нему экран вписывает куклу в доступную область, прозрачные поля холста не учитываются.
- Одежда может выходить за холст: шляпа выше макушки, подол шире картинки.

## Файлы вещи

`cloth-src/<категория>/<вещь>/`:

| Файл | Зачем | Обязателен |
|---|---|---|
| `catalog.png` | плитка в каталоге | да |
| `front.png` | передняя плоскость на кукле | да |
| `back.png` | задняя плоскость, за фигуркой | нет |
| `scale.json` | позиция на кукле | да |

`front.png` и `back.png` одного размера и ставятся в одну точку.

Из `scale.json` приложение использует только `offset_on_doll` — левый верхний угол `front.png` на холсте. Сборка ещё сверяет `doll_canvas` и `scaled_size`. Остальные поля — история подготовки картинки скриптом, их никто не читает.

```json
{
  "scaled_size": [342, 436],
  "doll_canvas": [768, 1376],
  "offset_on_doll": [215, 266]
}
```

## Инварианты, которые проверяет сборка

Задача `generateDatasetConfig` плагина `dressdoll.clothing.dataset`, та же, что проверяет `categories.json`. Все нарушения выводятся одним списком.

- В папке категории только папки вещей. Файл там `AssetManager.list()` выдал бы за вещь.
- В каждой папке вещи есть `scale.json`, `front.png` и `catalog.png`.
- `doll_canvas` равен размеру `doll_1.png`.
- `scaled_size` равен размеру `front.png`. `back.png`, если он есть, того же размера.
- `offset_on_doll` — массив из двух целых чисел.
- Вещь не лежит целиком за пределами холста: это почти всегда опечатка в `offset_on_doll`.
- На `doll_1.png` есть хотя бы один пиксель с альфой выше 12.

Проверяется только то, что AAPT упакует в ассеты: папки с `_` в начале, `.DS_Store` и другие файлы из `ignoreAssetsPattern` по умолчанию пропускаются.

Пиксели одежды на вход задачи не попадают, только размеры из заголовка PNG. Перерисованная картинка того же размера проверку не перезапускает.

## Что генерируется

`DollConfig.kt` рядом с `CategoriesConfig.kt`:

- `dollConfig` — размер холста и прямоугольник фигурки;
- `itemPlacements` — `offset_on_doll` каждой вещи.

`TemporaryDataset` берёт позицию вещи отсюда. Вещь без записи — ошибка в рантайме, как расхождение папок с конфигом: сборка генерирует запись для каждой папки вещи.
