# scale_cloth

Приводит изображения одежды к масштабу куклы. Масштаб берётся из `ondoll.pxd`, где одежда вручную подогнана по кукле в Pixelmator Pro.

## Входные данные

Скрипт обходит конечные папки `cloth-src/<тип>/<NN>/`. В каждой ожидаются:

| Файл | Обязателен | Что это |
|---|---|---|
| `ondoll.pxd` | да | Документ Pixelmator Pro. Нижний слой — кукла, второй снизу — одежда, надетая на куклу. |
| `front.png` | да | Одежда спереди. Холст W×H, вокруг одежды прозрачные пиксели. |
| `back.png` | нет | Одежда сзади. Холст того же размера и в той же системе координат, что у `front.png`. |
| `catalog.png` | — | Не используется. |

Папки, где нет `ondoll.pxd` или `front.png`, а также `ondoll.pxd` меньше чем с двумя слоями, пропускаются с сообщением.

## Запуск

Нужны Python 3, Pillow и numpy.

```bash
python3 scripts/scale_cloth/scale_cloth.py
```

```bash
python3 scripts/scale_cloth/scale_cloth.py cloth-src --only брюки/01
```

```bash
python3 scripts/scale_cloth/scale_cloth.py doll2_test
```

- Аргумент `root`: `cloth-src` целиком (обходит все подпапки с `ondoll.pxd`) или одна конечная папка. По умолчанию это `cloth-src` в корне репозитория.
- `--only <тип>/<NN>`: обработать одну папку внутри `root`.

В конце выводится сводка: сколько обработано, пропущено и сколько с предупреждениями. Код возврата 1, если что-то пропущено.

## Алгоритм

1. В `front.png` ищется bbox непрозрачного содержимого (alpha > 0): размер w×h, угол (x, y).
2. Из `ondoll.pxd` берётся второй слой (одежда): размер w'×h', угол (Lx, Ly) на холсте куклы. Слой уже обрезан по прозрачным краям.
3. Масштаб по осям: `s_x = w'/w`, `s_y = h'/h`. Ресайз непропорциональный: так одежда точно повторяет подгонку в pxd.
4. `front.png` масштабируется целиком, вместе с прозрачными полями, до `round(W·s_x) × round(H·s_y)` фильтром LANCZOS. `back.png` масштабируется с теми же коэффициентами, свой bbox для него не ищется.
5. Положение отмасштабированного холста на холсте куклы с учётом прозрачных полей:
   `offset = (round(Lx − x·s_x), round(Ly − y·s_y))`. Тот же offset подходит для back.

## Выходные файлы

Пишутся рядом с исходниками, сами исходники не меняются.

| Файл | Что это |
|---|---|
| `front_scaled.png` | Отмасштабированный `front.png`, RGBA. |
| `back_scaled.png` | Отмасштабированный `back.png`, если он есть. |
| `scale.json` | Параметры, см. ниже. |
| `_check.png` | Проверка: кукла из pxd на белом фоне и поверх неё `front_scaled.png` по `offset_on_doll`. |

`scale.json`:

```json
{
  "s_x": 0.3217,
  "s_y": 0.3136,
  "source_size": [289, 944],
  "scaled_size": [93, 296],
  "front_bbox": [34, 150, 230, 794],
  "layer_rect": [347, 291, 74, 249],
  "doll_canvas": [768, 1376],
  "offset_on_doll": [336, 244]
}
```

| Поле | Значение |
|---|---|
| `s_x`, `s_y` | Масштаб по осям. |
| `source_size` | Размер исходного холста `front.png`. |
| `scaled_size` | Размер `front_scaled.png`. |
| `front_bbox` | `[x, y, w, h]` содержимого в исходном `front.png`. |
| `layer_rect` | `[Lx, Ly, w', h']` слоя одежды на холсте pxd. |
| `doll_canvas` | Размер холста pxd. |
| `offset_on_doll` | Куда ставить левый верхний угол `front_scaled.png` и `back_scaled.png` на холсте pxd. Отсчёт от холста, а не от слоя куклы. |

## Предупреждения

- **`s_x` и `s_y` различаются больше чем на 1%.** Одежда в pxd растянута непропорционально. Обычно это сделано намеренно (у брюк доходит до 30%), но так же проявится и не тот `front.png`. Проверяйте по `_check.png`.
- **После ресайза содержимое не совпадает со слоем pxd больше чем на 2 px.** Обе картинки меряются по alpha > 32: при сильном уменьшении LANCZOS размазывает край на пару почти прозрачных пикселей, и bbox по alpha > 0 выходит на 2–5 px больше. Допуск 2 px нужен потому, что у слоя в pxd край мягче, и по порогу он на пиксель уже с каждой стороны.
- **Размер `back.png` не совпадает с `front.png`.** Тогда общий offset для back неверен.

## pxd_layers.py

Разбирает `.pxd` (zip с SQLite `metadata.info` и данными слоёв в `data/`). Функция `extract(pxd, out_dir)` сохраняет PNG каждого слоя верхнего уровня, обрезанный по непрозрачному содержимому, и `layers.json` с позициями в пикселях. Слои идут снизу вверх. Её можно запустить и отдельно:

```bash
python3 scripts/scale_cloth/pxd_layers.py cloth-src/брюки/01/ondoll.pxd
```

Вывод попадает в `ondoll_layers/` рядом с файлом. Там же сохраняется `_preview.png`, сборка всех слоёв.

Поддерживаются два вида слоёв:

- **Вставленная картинка**: файл `data/<id>-OriginalContentSource` (PNG). Размер слоя в pxd задан по непрозрачному содержимому.
- **Растровый слой, нарисованный в Pixelmator**: файл `data/<id>` без расширения, формат `PTBitmapBuffer`. Заголовок содержит ширину, высоту, байт в строке, потом блок формата `4-tP…` переменной длины, дальше raw deflate. Пиксели — BGRA с предумноженной альфой, строки сверху вниз. Размер слоя в pxd — весь буфер, поэтому прозрачные поля срезаются после расчёта позиции.

Позиция слоя в pxd хранится как центр в точках с осью Y снизу вверх; в пиксели переводится через `backingScale`.

Если слой уменьшали в Pixelmator, пиксели хранятся в исходном размере, а уменьшение лежит отдельно в `scale` (`sx, sy`). Видимый размер слоя равен `size × scale`, масштабирование идёт вокруг `anchorPoint`, обычно это центр. Если `anchorPoint` не в центре, а `scale` не равен 1, выводится предупреждение.

Ограничения: трансформации, поворот и группы слоёв не поддерживаются. На трансформацию или поворот выводится предупреждение, а слои внутри групп не читаются. Правки пикселей поверх вставленной картинки (`layer_tiles`) тоже не учитываются, с предупреждением.
